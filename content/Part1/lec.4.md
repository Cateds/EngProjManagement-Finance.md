## 项目沟通管理

项目沟通管理包括确保项目及其相关方的信息需求得到满足所需的各项流程。这通过制定文档以及实施旨在实现有效信息交换的活动来完成。

项目经理大部分时间都在与团队成员以及其他项目相关方沟通。这些相关方包括组织内部的各层级人员和组织外部的人员。因此，考虑到两两之间都有交流的可能，潜在的沟通渠道数量为 $\frac{n(n-1)}{2}$

沟通活动具有多个维度，包括但不限于

- 内部 & 外部
- 正式 & 非正式
- 层级焦点（向上/向下/横向）
- 官方 & 非官方
- 书面 & 口头

### 规划沟通管理

规划沟通管理 (Plan Communications Management) 是基于每个相关方或者群体的信息需求、可用的组织资产以及项目的需求，制定适合的项目沟通活动方法和计划的过程。

该过程的关键益处在于形成一种文件化的方法，通过及时呈现相关信息，有效并且高效地吸引相关方参与。

#### 技巧与注意事项

- 发送者-接受者模型
  - 通过纳入反馈回路，提供互动/参与的机会，并消除有效沟通的障碍
- 媒介选择
  - 何时采用书面或口头沟通，何时准备非正式的备忘录或正式的报告，以及何时使用推/拉式沟通和选择合适的技术
- 写作风格
  - 恰当使用主动语态与被动语态，注意句式结构和遣词造句
- 会议管理
  - 准备议程、邀请必要的参与者，以及处理会议中的冲突
- 演示技巧
  - 关注肢体语言的影响以及视觉辅助工具的设计
- 积极倾听
  - 主动倾听（确认、澄清和确认理解），并消除对理解产生不利影响的障碍

- 销售技巧

### 监控沟通

监控沟通 (Monitor Communications) 是确保项目及其相关方的信息需求得到满足的过程。

该过程的关键益处在于，根据沟通管理计划和相关方参与计划的定义，实现最优的信息流。此过程在整个项目期间执行。

## 项目风险管理

### 规划风险管理

规划风险管理 (Plan Risk Management) 是定义如何开展项目风险管理活动的过程。

该过程的关键益处在于确保风险管理的程度、类型和可见性与风险暴露水平以及项目对组织和其他相关方的重要性相匹配。

| 输入 | 工具与技术 | 输出 |
|------|-----------|------|
| 项目章程 | 专家判断 | 风险管理计划 |
| 项目管理计划 | 数据分析 |  |
| 项目文件 | 会议 |  |
| 事业环境因素 |  |  |
| 组织过程资产 |  |  |

#### 风险管理计划

风险管理计划 (Risk Management Plan) 是规划风险管理过程的输出和组成部分，描述了如何组织和执行风险管理工作。其包含以下内容

- 风险策略 (Risk strategy)
  - 描述管理项目风险的通用方法
- 方法论 (Methodology)
  - 定义将要使用的方法、工具和数据来源
- 角色与职责 (Roles and responsibilities)
  - 定义每项活动的负责人、支持者以及风险管理团队成员
- 资金 (Funding)
  - 识别执行活动所需的资金
- 时间安排 (Timing)
  - 定义风险管理流程执行的频率和时间点
- 风险类别 (Risk categories)
  - 提供一种对单个项目风险进行分组的方法。常见的风险分类方式是使用**风险分解结构 (Risk Breakdown Structure, RBS)**
- 相关方风险偏好 (Stakeholder risk appetite)
  - 每个项目目标的可衡量风险阈值，有助于确定可接受的项目风险暴露水平
- 风险概率和影响的定义 (Definitions of risk probability and impacts)
  - 概率和影响水平的定义需针对具体项目进行明确
- 概率和影响矩阵 (Probability and impact matrix)
  - 优先级规则可由组织在项目开始前预先制定，并可根据具体项目进行调整
- 报告格式 (Reporting formats)
  - 定义如何记录、分析和传达风险管理过程的结果
- 跟踪 (Tracking)
  - 记录如何记录风险活动以及如何审计风险管理过程

### 执行定性风险分析

执行定性风险分析 (Perform Qualitative Risk Analysis) 是通过评估单个项目风险的发生概率和影响，以及其他特征，对其进行优先级排序，以便进一步分析或行动的过程。

该过程的关键益处在于将精力集中在高优先级的风险上。此过程在整个项目期间执行。

### 执行定量风险分析

执行定量风险分析 (Perform Quantitative Risk Analysis) 是对已识别的单个项目风险和其他不确定性来源对整体项目目标的综合影响进行数值分析的过程。

该过程的关键益处在于量化整体项目风险暴露，并能提供额外的定量风险信息以支持风险应对规划。此过程并非每个项目都必需，但在使用时需在整个项目期间执行。

| 输入 | 工具与技术 | 输出 |
|------|-----------|------|
| 项目管理计划 | 专家判断 | 项目文件更新 |
| 项目文件 | 数据收集 |  |
| 事业环境因素 | 人际交往与团队协作技能 |  |
| 组织过程资产 | 不确定性表现方式 |  |
|  | 数据分析 |  |

#### 不确定性表示法

计划活动的持续时间内成本或者资源需求存在不确定性时，可能值的范围应该使用概率分布来表示。常用的分布包括三角分布，正态分布，beta 分布，均匀分布或离散分布等。

![[Pasted image 20260601033310.png]]

---

### 规划风险应对

规划风险应对 (Plan Risk Responses) 是制定备选方案、选择应对策略，并就如何应对整体项目风险暴露以及处理单个项目风险达成一致的过程。

该过程的关键益处在于确定应对整体项目风险和单个项目风险的适当方法。此过程在整个项目期间执行。

| 输入 | 工具与技术 | 输出 |
|------|-----------|------|

| 事业环境因素 | 人际交往与团队协作技能 | 项目文件更新 |
| 组织过程资产 | 威胁应对策略 |  |
|  | 机会应对策略 |  |
|  | 应急应对策略 |  |
|  | 整体项目风险应对策略 |  |
|  | 数据分析 |  |
|  | 决策 |  |

#### 威胁应对策略

应对威胁的策略一共有五种

- 升级上报 (Escalate)
- 规避 (Avoid)
- 转移 (Transfer)
- 减轻 (Mitigate)
- 接受 (Accept)

而应对机会 (Opportunity) 的策略则是类似，或者说对应的

- 升级上报 (Escalate)
- 利用 (Exploit)
- 分享 (Share)
- 增强 (Enhance)
- 接受 (Accept)

### 实施风险应对

实施风险应对 (Implement Risk Responses) 是执行已商定的风险应对计划的过程。

该过程的关键益处在于确保已商定的风险应对措施按计划执行，以应对整体项目风险暴露，最大限度地减少单个项目威胁，并最大限度地提高单个项目机会。此过程在整个项目期间执行。

| 输入 | 工具与技术 | 输出 |
|------|-----------|------|
| 项目管理计划 | 专家判断 | 变更请求 |
| 项目文件 | 人际交往与团队协作技能 | 项目文件更新 |
| 组织过程资产 | 项目管理信息系统 |  |

### 监控风险

监控风险 (Monitor Risks) 是监控已商定的风险应对计划的实施情况、跟踪已识别风险、识别并分析新风险，以及评估风险管理过程有效性的过程。

该过程的关键益处在于能够基于有关整体项目风险暴露和单个项目风险的最新信息做出项目决策。此过程在整个项目期间执行。
